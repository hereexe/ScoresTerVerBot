# План: Telegram-бот ScoresTerVerBot (учет активности на парах)

**Краткое резюме**
С нуля создаем Telegram‑бота на Python 3.10+ (aiogram 3.x) с MongoDB (motor). Реализуем регистрацию, выбор лекции, ввод баллов по типам активности, просмотр групповой статистики по лекции. Конфигурация через `.env`, состояния через FSM. Структуру проекта делаем модульной и тестируемой.

**Публичные интерфейсы/команды**
- `/start` — регистрация пользователя через FSM.
- `/menu` — главное меню с кнопками.
- `/add_lecture` — админ‑команда добавления лекции (дата).
- `/add_points` — запуск FSM добавления баллов (альтернатива кнопке).
- `/stats` — групповая статистика по выбранной лекции (альтернатива кнопке).

**Предлагаемая структура проекта**
- `bot/`
- `__init__.py`
- `config.py` — загрузка `.env`, типы, проверки.
- `db.py` — motor client, коллекции, индексы.
- `models.py` — Pydantic/TypedDict модели документов.
- `keyboards.py` — кнопки и inline‑клавиатуры.
- `states.py` — FSM состояния.
- `handlers/`
- `start.py` — регистрация.
- `menu.py` — главное меню.
- `lectures.py` — админ‑добавление лекций.
- `points.py` — FSM добавления баллов.
- `stats.py` — статистика.
- `main.py` — точка входа.
- `.env.example` — перечень переменных.
- `requirements.txt` (или `pyproject.toml`) — зависимости.

**Конфигурация**
- `BOT_TOKEN`
- `MONGODB_URI`
- `DB_NAME` (например `scores_bot`)
- `ADMINS` (список TG ID через запятую)

**База данных**
Коллекции:
- `users`: `{_id, tg_id, full_name}`
- `lectures`: `{_id, date_label}`
- `activities`: `{_id, user_id, lecture_id, type, value, timestamp}`

Индексы:
- `users.tg_id` unique
- `lectures.date_label` unique
- `activities.lecture_id`
- `activities.user_id`
- `activities.type`

**FSM сценарии**
1. Регистрация:
- `/start` → проверить `users` по `tg_id`.
- Если нет: запросить ФИО → сохранить документ.
2. Добавление баллов:
- Выбор лекции (список `lectures`, кнопки).
- Выбор категории (`questions`, `typo`, `professor`).
- Ввод значения (float).
- Сохранение `activities`.

**Статистика (по лекции, групповая)**
- Пользователь выбирает лекцию.
- Ответ: агрегированные суммы по типам и общий итог по всей группе.
- Опционально: топ‑5 по сумме.

**Валидации и ошибки**
- ФИО не пустое, минимум 2 слова.
- Значение баллов: float > 0 (можно ограничить до 0–10).
- Нет лекций → предложить администратору добавить.
- Проверка прав на `/add_lecture` по `ADMINS`.

**Команды разработки**
- Запуск: `python main.py`
- Установка: `pip install -r requirements.txt`
- (Если будет `pyproject.toml`) `pip install -e .`

**Тесты**
- Минимум: unit‑тесты на парсинг ввода и агрегации статистики.
- Фреймворк: `pytest`.
- Название: `tests/test_*.py`.

**Сценарии проверки**
- Новый пользователь проходит регистрацию.
- Добавлена лекция админом.
- Пользователь добавляет баллы (по всем категориям).
- Статистика по лекции возвращает корректные суммы.
- Некорректный ввод баллов → запрос повторить.
